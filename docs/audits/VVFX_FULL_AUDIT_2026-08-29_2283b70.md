## 3. Scope, methodology, evidence standard, and limitations

The audit covered the checked-in editor, model/evaluator, preview, persistence, all export paths, packaged runtime, UI/accessibility, performance/resource design, security/privacy, dependencies, code health, tests, CI, docs, hosting configuration, package integrity, and rollback/release flow.

Methods:

- pinned revision, refs, tags, cleanliness, environment, dependencies, and canonical commands;
- read the product, architecture, format, capability, runtime, roadmap, and release claims against current source;
- traced authored state through normalization, deterministic evaluation, preview, persistence, project/template/runtime exports, generated TypeScript, package load, host Phaser ownership, and cleanup;
- ran the complete release gate from a clean archive and separate focused model/security test groups;
- inspected package contents, source maps, hashes, bundle composition, CI permissions/actions, lockfile resolution/integrity, input limits, browser APIs, and network/dynamic-code surfaces;
- attempted the supported in-app browser workflow; it was unavailable, so repository Playwright is classified only as Automated evidence;
- calculated default-theme contrast from source tokens and ran a bounded single-frame GIF encoder measurement; no maximum tab-locking export was attempted;
- deduplicated symptoms under their root cause and kept C1 hypotheses out of the finding register.

Evidence classes used throughout:

- **Observed** — direct running-product reproduction. None was claimed because hands-on browser control was unavailable.
- **Automated** — tests, build, audit, archive comparison, or measured microbenchmark.
- **Static** — current source/contract trace.
- **Inferred** — projection or risk with a missing link, labeled explicitly.
- **Blocked** — intended work prevented by the no-browser/no-deployment/no-hardware condition.
- **Not tested** — not executed, although it could be a future qualification task.

The report treats passing tests narrowly. Shared evaluator code supports parity but does not prove physical renderer parity; the one post-GC browser assertion does not prove leak freedom; a clean advisory database result is not a security guarantee; and the absence of app network calls does not establish deployed response policy.

## 4. Architecture, data flow, and trust-boundary map

```text
Untrusted local input / persisted records / host runtime options
       |
       v
React editor workflows ---- browser permissions and fallible APIs
       |                              |
       v                              +--> FileReader / Image decode
Authored VfxProject (source of truth) +--> localStorage / IndexedDB
       |                              +--> Clipboard / Blob / MediaRecorder
       v
Bounded parse -> validation -> migration -> canonical normalization
       |
       +--> project / template / recovery persistence
       +--> project file and template-pack portability
       |
       v
Deterministic semantic evaluator (project + seed + time + options)
       |
       +--> Phaser editor preview -> capture canvas -> GIF/WebM download
       +--> Runtime JSON
       +--> Advanced TypeScript embedding the exact definition
       v
@vvfx/phaser-runtime validation -> private asset leases -> host Phaser scene
       |
       v
completion / restart / explicit destroy / shutdown / rollback cleanup
```

Ownership and dependency findings:

- Authored project data is canonical; evaluated instances are derived. `src/vfx` has no React dependency.
- The runtime externalizes Phaser and reuses core validation/evaluation rather than maintaining a second behavior engine.
- Static import analysis found 78 production TS/TSX modules, 238 runtime edges, and no runtime dependency cycle; one reciprocal edge is type-only and erased.
- Project, template, runtime, image, and persisted-record boundaries apply explicit count, byte, pixel, depth, identifier, finite-number, reference, and cycle checks.
- The preview/runtime boundary owns created sprites/listeners/filters and maintains texture leases. `RUNTIME-001` is the specific exception for frames added to an explicitly mapped host texture.
- Browser-local privacy is the intended design: no account/backend/cloud save and no application fetch/XHR/WebSocket/telemetry/remote-font path was found.
- CI/action code and registry packages are the primary remote-code trust boundary. Static hosting adds a deployed response-policy boundary, but no target was bound for inspection.

Concrete cross-layer risks are limited to the findings register. Large files are not defects by size alone; `CODE-002` is reported because one module mixes pure schema/evaluation and Phaser resource ownership, widening review and migration blast radius.

Product-boundary conclusions:

- Experimental WebGL effects may truthfully disable/degrade under Canvas according to the capability matrix; correctness means matching that documented fallback, not inventing shader parity.
- VVFX is a focused 2D VFX compositor/runtime, not an image editor, shader graph, scene-refraction system, or general physics/compositing engine.
